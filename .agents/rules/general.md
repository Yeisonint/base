# General workflow

- Write all code, comments and documentation in English unless the user explicitly requests another language.
- Before modifying code, analyze the full context of the file and its direct dependencies. Do not assume signatures, structures or contracts.
- Before writing code, briefly describe the approach and the files you will create or modify. Wait for approval on complex tasks.
- Apply minimal intervention: do not refactor or change working code outside the scope of the task, and respect the existing style.
- Never truncate code or use placeholders; always deliver complete modified functions or blocks.
- Before implementing changes, identify the project's language, framework, version, build system, dependency manager and testing tools.
- Respect existing versions and constraints. Do not upgrade languages, frameworks, compilers or dependencies unless it is an explicit part of the task.
- Before creating a new solution, check whether the project already has a utility, abstraction, component or pattern that solves the problem.
- Use the scripts and commands defined by the project before inventing alternative procedures.
- When a technical decision has several reasonable alternatives, briefly compare them and choose the most suitable one given the existing constraints.
- Do not invent APIs, functions, files, commands, versions or tool behavior. Check the documentation or existing code when uncertain.
- If critical information is missing to implement a task correctly, ask only for the information needed instead of assuming.
- When commands are requested, provide the complete, ready-to-run command.
- Keep responses short and direct; explain in more detail only when asked.
